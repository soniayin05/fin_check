## Stage 1: quota-independent product flow — implemented

- Add the offline numeric form using existing deterministic calculations.
- Save exact inputs, source observations and data/code fingerprints.
- Reopen old numeric and memo reports without model calls, preserving original
  values and warning when the current facts snapshot differs.
- Validate supported, contradicted, missing-year, growth, ratio and precision
  behavior; preserve existing scoped-agent tests. See `docs/OFFLINE.md`.

## Stage 2: manual claim review and memo-level development evaluation

Add PDF ingestion/page preview without model extraction and let users enter or
correct quotations and scope. Revalidate exact quote offsets and qualifiers;
preserve edit history rather than silently changing an approved claim. Connect
eligible historical numeric entries to the deterministic checker, while keeping
forecasts, segments and ambiguous/adjusted claims flagged. Build independently
annotated development memos to measure coverage, atomicity, qualifier retention,
evidence and correction accuracy. This stage can progress without Gemini.

## Stage 3: complete experiments, freeze and final evaluation

When API access permits, finish embedding/hybrid retrieval and human candidate
review, then the retrieval answer experiment. Resolve source-independence and
gold decisions. Use dev traces to improve wrong-period/tool-choice behavior and
rerun a consistent full comparison. Finalize code/data/configuration/scoring,
record a freeze, then independently author the held-out set and preselect repeated
cases. Run the three systems under that freeze, retain failures and prepare the
report/demo. Do not create or tune on final held-out cases during these dev changes.

Optional memory, OCR and multimodal chart extraction are lower-priority additions
after the core evaluation evidence is complete. No final freeze or held-out run
has been claimed by implementing the offline interface.
